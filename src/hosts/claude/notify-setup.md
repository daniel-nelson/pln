**Notification setup**: run this on every `/pln` invocation, before anything else — a brand-new plan, a "continue the plan we started", a reopened decision, all of it. It is deliberately not part of Step 1 pre-flight below: that step only runs before writing a new plan skeleton, so a "continue" invocation would skip it, and notification setup can't skip with it. pln can pull the user back before every user-input wait and at completion over two independent channels, each separately toggleable and both default on:

- **Phone push**, via the harness `PushNotification` tool. Reaches the user's phone when they're away from the terminal, and self-suppresses when they're actively watching it. Gated on `notify_push`. Read `${CLAUDE_SKILL_DIR}/bin/pln-config get notify_push`; unless it prints `false`, push is on — call `ToolSearch` with query `select:PushNotification` **once now**, so the tool is loaded before the Step 3/5/7 call sites need it (it is commonly a deferred tool, unloaded until requested). If it prints `false`, don't load it and don't call it anywhere.
- **Local desktop notification**, via `${CLAUDE_SKILL_DIR}/bin/pln-notify-desktop "<message>"` (macOS/Linux). Covers the case the push channel's self-suppression takes away: the user is at the computer, so the push stays quiet but the desktop notice still fires. Needs no setup here — the helper self-gates on `notify_desktop` and no-ops on an unsupported platform, so the call sites invoke it unconditionally.
