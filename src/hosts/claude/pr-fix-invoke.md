Launch every cluster as a non-fork `general-purpose` Agent with a stable name such as `pln-pr-fix-<K>` and background execution. Record every returned agent ID before waiting. Each agent has `commit owner: coordinator`: it edits only its leased paths, runs focused verification, does not touch the shared `REVIEW.md`, and returns a non-empty summary naming changed files, cleared findings, and tests.

Wait for completion notifications until every cluster is complete, failed, or blocked. A failed/API-error notification or empty result is a failed cluster, not a clean one. Because write leases are disjoint, successful clusters may finish in any order; validate that their reported paths match their leases, then commit them one cluster at a time by explicit path with the co-author trailer — never `--amend`, never `--no-verify`, never `git add -A`. After each commit, the orchestrator alone writes `fixed` plus that hash against the cluster's findings in `REVIEW.md`, so checkpoint writes never race.

If a cluster returns `BLOCKED:`, leave its paths uncommitted and commit no byte from its lease. Other successful disjoint clusters may still checkpoint by their own explicit paths. Surface the one question, record the answer in `REVIEW.md`, then `SendMessage` the blocked agent by ID with the answer and tell it to continue from its existing work. Wait for its next completion notification, validate its lease, and commit it only after it finishes. If the native handle is genuinely lost, start a fresh Agent on the answer, handoff, and uncommitted diff. On an older/disabled native host, the guarded `pln-claude-agent` fallback does the same work serially and resumes a blocker with a fresh one-shot worker on those artifacts.
