Once the schedule is validated, the main session is a thin coordinator: it owns the manifest, `PLAN.md`, every git checkpoint/integration, and user interaction, but never item implementation. Codex native agents share the caller's filesystem, so isolation is an explicit standard git worktree created by the coordinator before spawn.

For each ready manifest wave:

1. Allocate one bounded temporary worktree root for the run. For each `isolated` lane, create an explicit child with `git worktree add --detach <path> <recorded-source-or-predecessor-commit>` and write that path to the manifest before `spawn_agent`. Never derive a cleanup target from an unset variable or broad directory. A `reuse` cohort node keeps its predecessor's worktree. An `original` node runs serially in the source worktree and never overlaps another writer there.
2. Spawn every disjoint isolated member of one wave with `fork_turns: "none"`, a stable task name, and a one-item brief naming its exact worktree and lease. Record each returned agent identity and `running` state before launching the next. Wait through the bounded mailbox loop until all wave members are complete, blocked, or failed. Native agents may run concurrently; nested CLI fallbacks remain serial because their OAuth state can race.
3. A failed agent, empty result, malformed envelope, or write outside the lease fails that node; preserve its artifacts, mark the manifest, and force a fresh boundary. A blocked member follows the blocker phase. Successful siblings may be validated and checkpointed in their own worktrees, but not integrated across a blocker.
4. The coordinator validates each result and diff, stages only explicit leased paths with `git -C <worktree> add -- <paths>`, and creates the item commit with the required co-author trailer. Workers always receive `commit owner: coordinator` and edit neither git nor `PLAN.md`. Record result, actual route, commit, and `checkpointed` status immediately.
5. Integrate checkpointed commits into the source worktree strictly by manifest integration order, after dirty-state validation, then update `PLAN.md` and mark each node integrated. A conflict, unexpected write, corrected premise, or dirty-state mismatch stops integration and forces a fresh worker boundary after reconciliation.
6. When the next ready item is a `reuse` node in the same cohort, its predecessor is checkpointed, and the retained agent/worktree are intact, use `followup_task` on that idle identity with a new one-item brief. This is another turn after a durable item checkpoint, never one uncheckpointed multi-item prompt. Otherwise spawn a fresh agent. Stop reusing after three cohort nodes.

Persist an interruption before acting on it: mark each affected manifest node `interrupted`, record its retained worktree and last durable result, then use `send_message` for a steer or `interrupt_agent` for a real stop. Integrate nothing unfinished. Recovery may use `followup_task` on a retained identity or spawn a fresh agent on the item, handoff/result, and worktree when the identity is gone.

Only after a node is integrated and no recovery points to its worktree may the coordinator remove that exact worktree with `git worktree remove <recorded-path>` and prune its empty run directory. On an older/disabled host without native collaboration, disclose the fallback and run fresh workers serially in the original tree through `pln-codex-agent`; do not claim isolated concurrency or cohort continuity on the nested path.
